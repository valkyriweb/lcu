# LCU 0.13.4

**Keeps the Claude Code approval mod free of machine-specific paths, so a skills folder kept in a repository stays clean.**

## Changes

- **Claude Code: no `lcu.json` for a default install.** `lcu setup --agent claude-code` wrote `lcu.json` beside the `lcu-approve` mod with the absolute path of the `lcu` command, which tied a skills folder kept under version control to one account and left a diff on every other machine. The mod already falls back to `$HOME/.local/share/lcu/current/bin/lcu`, so setup now writes `lcu.json` only when that fallback would not find this installation (a custom prefix, or `$HOME` unset), and removes an earlier one otherwise ([#71](https://github.com/amontlabs/lcu/issues/71), [#72](https://github.com/amontlabs/lcu/pull/72), thanks @km-tr for the report).

## Upgrading

Run `lcu update`, then restart Claude Code; the update refreshes the mod at `~/.claude/skills/lcu-approve`. If you set up Claude Code with `--scope project`, run `lcu setup --agent claude-code --scope project` again. To go back, reinstall 0.13.3.
