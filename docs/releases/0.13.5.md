# LCU 0.13.5

**Keeps the Windows candidate installing on current ChatGPT app builds, which are now webpack bundles.**

## Changes

- **Windows candidate: native-pipe host extraction from webpack builds.** From `OpenAI.Codex` `26.1027.3384.0` the app has no `main*.js`, and the host factory sits inside the module that starts the app, so the installer stopped with no host factory found. LCU now finds the factory by its content, extracts it from that module, and runs it on a runtime derived from the app's own entry, without starting the app. The installer loads the written host once with Electron blocked and stops if that fails, so a host that cannot load is caught at install, not at first use. Earlier app builds keep working. Windows stays a candidate: this was checked on the official Windows and Linux bundles from macOS, not on a live Windows desktop ([#82](https://github.com/amontlabs/lcu/issues/82), [#83](https://github.com/amontlabs/lcu/pull/83), thanks @Xiao1804 for the detailed report).

## Upgrading

macOS and Linux behave as before; run `lcu update` if you want to stay current. To go back, reinstall 0.13.4.
