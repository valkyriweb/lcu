# LCU 0.13.2

**Stops the "Stop hook error" Claude Code shows on every turn when LCU's MCP server is not connected, and lets Pi-Bolt compile LCU into Pi.**

## Changes

- **Claude Code: no hook errors when LCU is not connected.** LCU's Claude Code lifecycle hooks were `mcp_tool` hooks on the `lcu` server. When that server failed to connect, for example after a startup timeout, Claude Code reported each of them as an error, so every turn ended with `Stop hook error: MCP server 'lcu' not connected`, even in sessions that never used Computer Use. Reproduced with Claude Code 2.1.311. The `PreToolUse`, `Stop`, `StopFailure` and `SubagentStop` hooks are now command hooks. They run a small helper that setup copies to `~/.local/share/lcu/claude/claude-hook.mjs` (Windows: `AppData\Local\LCU\claude\`). The helper reaches the running relay over a private lifecycle channel, and exits silently when no relay is running. When the relay is connected, turn binding and cleanup work as before: a turn is bound before `js` runs, and `Stop`, `StopFailure` and `SubagentStop` clean up the same turns and subagents. The relay waits for that channel before it offers Claude its tools, at most two seconds after the original server is ready. If the channel cannot start, Computer Use calls say so instead of failing with a missing identity. Checked with the real Claude Code CLI against a scripted API, both with no relay and with a connected relay; native Windows and the macOS desktop were not run. The separate 30-second connection timeout in the report is not changed by this; setting `MCP_TIMEOUT=60000` gives the server more time ([#64](https://github.com/amontlabs/lcu/issues/64), [#66](https://github.com/amontlabs/lcu/pull/66), thanks @valkyriweb for the report).
- **Pi: Pi-Bolt compiles LCU in.** On macOS and Linux, the Pi extension LCU writes to `~/.local/share/lcu/pi/extension.mjs` now imports the adapter by its plain path instead of a `file://` URL. `pi-bolt compile` does not follow a `file://` import, so it left LCU interpreted on every start. Stock Pi loads both forms, and the Windows wrapper is unchanged ([#65](https://github.com/amontlabs/lcu/pull/65), thanks @KorenKrita for the fix).

## Upgrading

Run `lcu update`, then restart your agents. The update replaces LCU's Claude Code hooks in your user settings. If you set up Claude Code with `--scope project`, run that `lcu setup` again in each project. For Pi, run `lcu setup --agent pi` again to rewrite the extension.

To go back, reinstall 0.13.1 and run its `lcu setup --agent claude-code` again to restore its hooks.
