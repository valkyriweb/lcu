# LCU 0.13.3

**Installs the Claude Code approval mod when `~/.claude/skills` is a symlink, and keeps LCU's update notices working in Team and Enterprise organizations.**

## Changes

- **Claude Code: the approval mod installs through a linked skills folder.** When `~/.claude/skills` (or a project's `.claude/skills`) was a symlink, for example into a dotfiles repository, `lcu setup --agent claude-code` refused to write the `lcu-approve` mod and reported it as an MCP failure. Setup now follows that folder to its real path once; it still refuses a link at the mod folder itself or inside it. A failed mod install is now reported as its own `approval mod` step, after the MCP server is registered, and the approval mode still applies ([#67](https://github.com/amontlabs/lcu/issues/67), [#69](https://github.com/amontlabs/lcu/pull/69), thanks @km-tr for the report).
- **Claude Code: update notices in Team and Enterprise organizations.** In those organizations Claude Code's built-in guard (`cc-plugin-sec-default@builtin`) skips the `classic.*` hooks of mods a person installs. The mod's update notices now run on `session.start` and `prompt.submit`, which the guard does not skip. The mod's approval pane still needs `classic.Elicitation`, the only event Claude Code has for an MCP elicitation, so in those organizations approvals use Claude Code's own form instead. [ADAPTERS.md](../ADAPTERS.md) describes what works there. Not run in an organization account ([#68](https://github.com/amontlabs/lcu/issues/68), [#69](https://github.com/amontlabs/lcu/pull/69), thanks @km-tr for the report).

## Upgrading

Run `lcu update`, then restart Claude Code; the update refreshes the mod at `~/.claude/skills/lcu-approve`. If setup failed on a linked skills folder before, or you set up Claude Code with `--scope project`, run `lcu setup --agent claude-code` again (with the same scope). To go back, reinstall 0.13.2.
